Pre-training Settings. Our settings mostly follow [\[15,](#page-9-1) [14\]](#page-8-0). Table [3a](#page-13-1) summarizes our contrastive pre-training settings on MedMNIST, following [\[15\]](#page-9-1). Table [3a](#page-13-1) shows the corresponding pre-training settings on CIFAR-10-LT, following the official MoCo demo on CIFAR-10 [\[14\]](#page-8-0). The contrastive learning model is pre-trained on 2 NVIDIA RTX3090 GPUs with 24GB memory each. The total number of model parameters is 55.93 million, among which 27.97 million requires gradient backpropagation.

Dataset Augmentation. We apply the same augmentation as in MoCo v2 [\[15\]](#page-9-1) on all the images of RGB modalities to reproduce the optimal augmentation pipeline proposed by the authors, including PathMNIST, BloodMNIST, CIFAR-10-LT. Because OrganAMNIST is a grey scale CT image dataset, we apply the augmentation in [\[3\]](#page-8-1) designed for radiological images, replacing random gray scale and Gaussian blur with random rotation. Table [4](#page-13-0) shows the details of data augmentation.

Repeated Augmentation. Our MoCo v2 pre-training is so fast in computation that data loading becomes a new bottleneck that dominates running time in our setup. We perform repeated augmentation on MedMNIST datasets at the level of dataset, also to enlarge augmentation space and improve generalization. [\[21\]](#page-9-0) proposed repeated augmentation in a growing batch mode to improve generalization and convergence speed by reducing variances. This approach provokes a challenge in computing resources. Recent works [\[21,](#page-9-0) [50,](#page-10-0) [7\]](#page-8-2) proved that fixed batch mode also boosts generalization and optimization by increasing mutiplicity of augmentations as well as parameter updates and decreasing the number of unique samples per batch, which holds the batch size fixed. Because the original contrastive learning works [\[13,](#page-8-3) [15\]](#page-9-1) were implemented on ImageNet dataset, we attempt to simulate the quantity of ImageNet per epoch to achieve optimal performances. The details are shown in Table [5.](#page-14-0)

We only applied repeated augmentation on MedMNIST, but not CIFAR-10-LT. This is because we follow all the settings of the official CIFAR-10 demo [\[14\]](#page-8-0) in which repeated augmentation is not employed.
