methods are ready to be used on the frame. When a frame is sent from the camera, an inference graph (making the predictions) will be run on that single frame. The output from the graph is used to draw the bounding boxes around each of the items detected. Showing the inference on the frame is configured to have normalized coordinates and bounding boxes can only be drawn if the confidence of the prediction exceeds 80 percent. From these bounding boxes we can extract the information required such as the center of the item, enabling the process of drag and drop.

### 5.4 Localization

Localization is the process of translating pixel values to real life coordinates. The pixel values are nothing, but the center of the objects detected by the Machine Learning model. The real-life coordinates are the  $ (x, y) $ coordinates of the virtual grid or the workspace table over which the objects are placed.

Following the detection and computation of the center pixel locations of all the objects placed on the workspace table, the locations must be mapped into real life coordinates. This is done using the'map' function in python; however, this requires the camera's field of view to be directly positioned on top of the virtual grid, meaning that the top left side of the camera must exactly match the top left coordinate of the virtual grid which is very exacting and inaccurate. This problem was solved by using 'AprilTags'.

AprilTags are like QR codes; however, they are designed to encode smaller data payloads, allowing them to be detected from longer ranges and with a higher accuracy.

Using the ‘pupil-apriltags’ library in python, the tags can be easily detected by the camera using what is known as the ‘AprilTags detector’. The detector then returns an array containing details of the tags such as the tag id, tag family, pixel locations of the tag corners, and most importantly the center pixel location of the tags.
